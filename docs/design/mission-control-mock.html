P5 — attention: settled. flag by default, take the wheel only when nobody is here

Round one put two alternatives side by side. They are not alternatives any more. The policy is flag by default; take the wheel only when the user asked, or when the surface has been idle past a threshold — IDLE_MS = 90s in the shipped host — and urgency alone never promotes a flag to a jump.

That last part is enforced by the SHAPE of the event rather than by a rule someone has to remember: applet-attention carries applet and an optional count, and no severity field at all. An applet convinced its news is important has nothing to argue up with.

flag a lane blocks while you are reading

The surface moves to Files first, because the story needs you to be reading something else. Then a lane blocks. The Dashboard tab takes a flag — a dot when it is one thing, the count when it is more — and the surface does not move. Press it again and another lane blocks: the count replaces rather than adds, so two reports of three lanes mean three.

wheel a lane blocks after 90s of no interaction

The same event with the same fields, and one difference: nobody has touched this surface in a minute and a half, so moving it costs them nothing. The host switches tabs and leaves no flag behind. Then, a second later, a second thing wants a human in the same idle window — and it only gets a flag, because the jump recorded a gesture and the surface never yanks twice in a row.

The log is written by the same function that decides, so it cannot describe a jump the surface did not make. The second event in the wheel demo comes from Pull Requests, because the difference is only visible on a tab you are not on. What the shipped applet can actually notice today is narrower: it polls only while active, so its red-check diff is dormant until pull-request state arrives from something that keeps watching while you are elsewhere. The host's decision is what this demonstrates, and that part is built.

Not built: a banner explaining the move. Round one proposed one; the shipped host paints nothing extra when it takes the wheel — it clears the flag, and the surface is simply there.

what the host does while you are not looking

The tab strip mounts every applet all the time and hides all but one, so scroll position, an open disclosure and where you had navigated to all survive a trip to another tab and back. That is exactly why the inactive rule needs teeth: hiding a thing does not stop it working, so the host tells each applet whether it is active, and an inactive applet must go quiet — drop its timers, its subscriptions, and the request that was already on the wire. (This prototype re-renders one applet into one body, because three mounted applets buy a mock nothing. The claim is about the shipped host.)

Measured, not asserted. With Pull Requests active its 60s poll fired: 1 request at T0, 3 by T+75s. Switching away froze it — still 3 after 140 further seconds inactive, more than two poll intervals with nothing on the wire. The Files applet, mounted for the whole session but never activated, issued zero requests.

The one documented exception is the Dashboard's, and it is documented as one: it keeps a store subscription while inactive, and its entire inactive response to a fleet change is one integer comparison — no re-render, no DOM, no fetch, no timer. It opens nothing, polls nothing and paints nothing. Without it the surface cannot tell you a lane blocked while you were reading a diff, and a flag you only get when you look is not a flag.

Portrait. The host is inert — every applet inactive, so the contract's one rule holds for free on a phone — and the bottom sheet renders the same Dashboard applet rather than a second copy of the fleet. Files and Pull Requests are unreachable in portrait: the sheet carries the Dashboard only. That is the honest state and not a regression, because neither applet existed before. Giving the sheet the tab strip, with the rail collapsed into a ⋯ menu, is still the right sketch and still unbuilt.

P3 — what Files is rooted at, and why the letters are letters

A picker over known roots, not the active pane's cwd. With eleven worktrees on this machine a single root is wrong within a day; pane-scoping it would make the Files tab mean something different every time focus moved. The candidates are the distinct project paths of the live fleet, plus the server's own working directory as the fallback. The picker sits in the applet body and not the rail, because the rail is shared chrome painted in the host's vocabulary and a <select> is not in that vocabulary.

The status column carries git's own letter — M A D ? R U for modified, added, deleted, untracked, renamed and conflicted — in a fixed-width leading column and a colour. The letter is the point: the distinction survives a grayscale screenshot pasted into a ticket, and it survives a light palette. Unchanged rows get a blank of the same width so the column cannot jitter as a worktree goes dirty under you, and a directory shows M when anything beneath it changed — "there is something in here" is all a rolled-up row can honestly say.

A root's real identity is (machine, path), not path: two worktrees on two machines can share a path and are not the same place. The shipped row already carries the machine field, empty meaning this one. Remote roots arrive when read-only cross-machine file reads land — branch feat/remote-read-only-fs, PR #92, unmerged — and this round lists local roots only, because offering a root we cannot open would be a lie told in a dropdown. When #92 lands the change here is: stop filtering remote sessions out, and pass machine through. No row shape changes.

P4 — where these pull requests actually come from

Not the sessiond watchlist. What shipped asks the host's own already-authenticated gh over the repos of every root the browser has ever seen — the live fleet's local project paths, union everything it has scanned before. The remembering is the load-bearing part: a lane that exits takes its row out of the fleet at exactly the moment you want to know what it opened.

What that is not, plainly. It is not attribution: no GitHub API can say which lane opened a pull request, and this applet does not claim to — which is why no row here names one. It is not durable: a browser-local memory dies with the profile and is invisible to every other client. The durable answer is the D2 watchlist owned by sessiond, fed by muxterm session report --pr N — which still nothing calls — with dismissals in a separate store so a re-scan cannot resurrect them. That is a follow-on, named rather than half-built, and the row shape does not change when it lands.

Dismissal is muxterm state and never GitHub state, keyed owner/repo#number, and nothing is ever pruned from the set. A dismissed row never comes back on its own — not when its checks go red, not when a later scan finds it again. A dismissal that undoes itself is not a dismissal.

what this prototype is claiming

  • P1The shell. The surface is Mission Control; the applet is Dashboard; "chief of staff" is the role the assistant plays, and muxterm is the product. The topbar carries the title and the ⋯ menu and nothing else — the struck-through cards | tiles marks where the toggle used to be pinned. Applet-owned controls live in the control rail at the right end of the tab strip. The host paints the rail; the applet fills it, in the host's vocabulary, and nothing destructive is allowed there.
  • P2Dashboard. The fleet view, moved in whole and unchanged in geometry — same fixed-height card contract, same three groups (wants you / working / done), same 3px state border. Its cards/tiles switch is now its own, in the rail, and there is exactly one of it. The #84 chips on cards are still a proposal: navigating from one applet to another is settled and allowed from a user gesture, but nothing in the shipped code fires applet-navigate yet. Click one anyway.
  • P3Files. One directory at a time: a root picker over known worktrees, clickable breadcrumbs, the branch dim at the right, and git's own letter in a fixed-width column with a blank of the same width where there is no change. Directories navigate; files are names, because no row opens a file this round. changed only in the rail collapses the listing to just the work.
  • P4Pull Requests. Every open pull request across the worktrees this surface has seen. A row is the number (coloured by checks), the title as a link, one badge geometry for draft / checks / review decision, and branch · author · age underneath. Dismiss is an X in the row, never in the rail; the rail carries only dismissed (N), and it is absent entirely when nothing is dismissed. Dismiss means stop showing it here, never close the PR.
  • P5Attention. One settled policy, demonstrated above: flag by default, the wheel only when you asked or after 90s untouched, and no way for a caller to argue urgency.
