### Exact command that restores the previous version

```sh
cp /home/ken/tmp/muxterm-v0.29.0.bak /home/ken/.local/bin/muxterm && \
  systemctl --user restart muxterm-sessiond.service muxterm.service
```

### Deploy method

muxterm's own upgrade machinery under `internal/update`, driven through the owner-only
`POST /api/update/apply` route, rather than a hand-rolled stop-and-start. That path verifies the
GoReleaser checksum before installing, renames atomically on the same filesystem, and — because
`[restore] enabled = true` in the config — restarts `muxterm-sessiond.service` and `muxterm.service`
in one invocation so systemd's `After=` ordering holds and the daemon is never left version-skewed
under a newer web process.

The running server already sees the release:

```
$ curl -H "Authorization: Bearer <local token>" http://127.0.0.1:9090/api/update/status
{"currentVersion":"0.29.0","latestVersion":"0.30.0","updateAvailable":true,
 "canUpdate":true,"devBuild":false,"method":"binary"}
```
