## S4 — the containment argument, on the merged main (468cb1b) · PASS 4/4

#109's whole security claim is that a request **selects an entry from a fixed manifest** and never
**builds a path**. All four required properties hold on the merged tree.

### (1) The URL tail is a map key only; the opened path is rebuilt from the manifest

```
internal/server/publish_folder_api.go
78:	rest := r.PathValue("rest")
79:	key, err := normalizeTreeRequest(rest)
--- every use of the derived key, in the whole file ---
87:	if dir, isDir := p.tree.dirs[key]; isDir {
92:		if key != "" && !strings.HasSuffix(rest, "/") {
100:	tf, isFile := p.tree.files[key]
112:	s.serveTreeFile(w, p, base, parentKey(key), tf)
```

Two map lookups, one emptiness test, one URL-building call. It is never joined into a filesystem
path. The read path's only path-builder takes the **manifest's** relative path:

```
$ grep -rn "resolveInTree(" internal/server/
publish_folder.go:336:func resolveInTree(t *folderTree, rel string) (string, error) {
publish_folder.go:407:	resolved, err := resolveInTree(t, tf.rel)      <-- tf.rel, a manifest field
publish_folder.go:337:	joined := filepath.Join(t.root, filepath.FromSlash(rel))
```

and `treeFile.rel` is written in exactly one place, at enumeration time
(`addFile`: `t.files[rel] = &treeFile{rel: rel, ...}`).

`normalizeTreeRequest` **validates and refuses**; it does not rewrite. A segment that is `..`,
`.`, empty, or carries a NUL or a separator is refused outright, and `path.Clean(rest) != rest`
refuses anything that could say the same path two ways.

### (2) Containment is `filepath.Rel` on resolved paths, not `strings.HasPrefix`

```go
func containedIn(root, abs string) bool {
	if root == "" || abs == "" { return false }
	if abs == root { return true }
	rel, err := filepath.Rel(root, abs)
	if err != nil { return false }
	if rel == "." { return true }
	if rel == ".." || strings.HasPrefix(rel, ".."+string(os.PathSeparator)) { return false }
	if filepath.IsAbs(rel) { return false }
	return true
}
```

The single `HasPrefix` is the rejection test on `Rel`'s **result**, which is the correct use, not a
containment prefix test. Both arguments are `EvalSymlinks` results: `resolveInTree` resolves the
join and only then asks `containedIn(t.root, resolved)`. A symlink that leaves the root resolves
to a path that fails containment and is refused.

The root is pinned by device and inode and re-proved on **every** read (`verifyTreeRoot`), the
exclusion policy is re-applied per read rather than trusted from enumeration time, `openPinnedPath`
refuses a symlink at any component and opens with `O_NOFOLLOW`, and `readAllBounded` re-applies the
size bound per read.

### (3) `.git` is excluded unconditionally, at every depth

```go
if strings.HasPrefix(name, ".") {
	if name == ".git" {
		return true, "a .git directory is never served: it carries the repository's entire history"
	}
	return true, "dotfiles and dot-directories are never served"
}
```

`folderExcluded` splits the whole relative path and tests **every** component, so a file whose
parent is excluded is excluded too — and it is called both at enumeration and again inside
`readTreeFile` ("the exclusion policy, re-applied per request rather than trusted from
enumeration time").
