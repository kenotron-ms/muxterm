### What v0.26.0 contains

Everything merged since `v0.25.0` (= `50cc66f`), four substantive changes:

1. **#94 — "reconnect promptly after a server restart"** (`cbd3346`, merged
   `15bca15`). *Already on main since before this lane; released here for the
   first time.* Retuned backoff ladder — `FAST_DELAY_MS = 300`,
   `BACKOFF_BASE_MS = 500`, `BACKOFF_CAP_MS = 5_000`, i.e.
   0.3,0.3,0.3,0.5,1,2,4,5,5,5s replacing 1,2,4,8,16,30,30s — and the ladder is
   forfeit the instant the user returns: `visibilitychange`, `focus` and
   `online` each fire an attempt immediately. Three honest overlay states
   (retrying / waiting-with-countdown / offline) and a working "Retry now".
2. **The WebSocket heartbeat** (`86e421b`, merged `69e9d4c` = #103). *Already on
   main; released here for the first time.* Server-side `conn.Ping` every 25s
   with a pong wait, keeping the connection warm through proxy idle windows and
   Android Doze. An unanswered ping kills the connection on purpose.
3. **#95 — "a second sessiond steals a live daemon's socket name"**
   (`0d47a9a` + `02cdf3a`, merged `dc1f127`). The release's reason to exist;
   verified live in S1.
4. **#96 — "untrack machine-local `web/node_modules` symlink"** (`04d83bd`,
   merged `564dd6b`).

### The third fix does not exist

The brief listed a third already-merged-but-inert item: *"the sessiond
unknown-request default case: an unrecognised wire request is now refused with a
named error instead of being silently dropped, which previously presented as a
false 45-second 'machine is unreachable'."*

**There is no such change in this repository.** Evidence:

* The control-message switch in `internal/sessiond/server.go` (arms
  `TypeCreateWorkspace` … `TypeSessionStateSubscribe`) ends at its closing brace
  with **no `default:` arm**. An unrecognised type falls through and is dropped.
* `git log --all -S` across every ref for `CodeUnknownRequest`,
  `"unknown request type"` and `"unknown-request"` returns **nothing**.
* Empirically, against the running v0.25.0 daemon:

```
=== send production's daemon a request type it does not implement ===
DIAL OK but NO REPLY after 8008ms (TimeoutError) -- request 'this-request-type-does-not-exist' silently dropped
=== control: a request type it DOES implement ===
DIAL OK in 0ms; reply type='workspace-list' ...
```

The 45-second symptom is real and its mechanism is confirmed:
`remoteCallTimeout = 45 * time.Second` in `internal/mcp/run.go:202` bounds one
cross-machine tool call. A request the remote daemon does not implement gets no
reply, waits out that bound, and surfaces as the machine being unreachable —
which is false. The design comments in `protocol.go` and `server.go` acknowledge
the silent-drop behaviour explicitly ("a daemon that predates this feature
ignores the unknown type and never replies").

So this release does **not** ship that fix, it is **not** claimed in the tag
message, and S6 does not verify it. Naming it and moving on, per scope-outs.
It is a genuine, unfixed defect and deserves its own PR.

**The exact command that restores the previous version:**

```bash
cp /home/ken/workspace/muxterm-ship-it-rollback/muxterm-v0.25.0 /home/ken/.local/bin/muxterm \
  && systemctl --user restart muxterm-sessiond.service muxterm.service
```

**Mechanism: muxterm's own upgrade machinery**, `POST /api/update/apply`
(`internal/server/update_handler.go` → `internal/update.Apply` + `Restart`),
not a hand-rolled stop-and-start. It downloads the release asset, verifies it
against `checksums.txt`, replaces the binary, and — because `INVOCATION_ID` is
set under systemd and `[restore] enabled = true` in the config — issues a single
`systemctl --user restart muxterm-sessiond.service muxterm.service`, which
systemd orders correctly via `After=`. `muxterm-sessiond.service` uses
`KillMode=mixed` so the daemon writes its shutdown snapshot before its children
die, which is what makes pane restore work at all.

`~/.config/muxterm/config.toml` is not read-modified-written by this path and is
not touched. The voice configuration (`model = "gpt-realtime-2.1-mini"`,
`auth_mode = "entra"`) is therefore undisturbed.

**The cost, stated plainly.** The restart kills the processes inside every pane.
Panes are restored from the crash snapshot; the *processes* in them are not.
Agent sessions do not survive — only their on-disk transcripts and completion
records do.

## Known and accepted — recorded, not fixed

Carried forward from #95's own list, deliberately not filled (out of scope):

1. **The probe-to-bind window is narrowed, not closed.** `ClaimSocket` probes,
   then `net.Listen` binds. A daemon coming up between the two can still be
   bound over. The spawn lock does not cover it, because a bare
   `muxterm sessiond` takes no lock. "Always destroys the incumbent" became "a
   millisecond-wide race" — a large improvement, not a proof.
2. **C4 has no test.** Neither `Hub.Add`'s threshold/counter-reset nor
   `sendDaemonUnreachable` is covered, and there is no frontend test for the
   `fatal` overlay.
3. **Stranded detection is Linux-only.** `stranded_other.go` returns false
   unconditionally; macOS gets the generic message. Prevention (C1) is
   platform-neutral — only the explanation degrades.
4. **`parentIsSystemd()` fails toward "gated".** An unreadable `/proc/<ppid>/comm`
   returns `true`, i.e. do-not-spawn.
5. **The commit message contradicts itself** about `INVOCATION_ID`'s parent
   chain (`bash -> muxterm -> systemd` in the header vs
   `amplifier -> bash, nowhere near systemd` in the code comment). Both readings
   support the same fix; the author is gone and cannot reconcile them.

Found during this lane, named and left alone:

6. **`sessiond` logs "listening" before it has claimed the socket.**
   A refused daemon prints
   `muxterm sessiond listening on <path>` immediately above its own fatal
   refusal. Cosmetic, log-only, misleading.
7. **The unknown-request silent drop** (S4) — real, unfixed, needs its own PR.
8. **20 pre-existing frontend test failures** (S3) — unrelated to this release.
