# Mission Control: multi-channel conversations

**Status:** design and staged PR plan, not an implementation or migration.

**Source baseline:** `origin/main` at `aa6b581bd8d8ba5537d794c33beed00e5755d2b8`, inspected 2026-09-11. File/line references below use that commit unless marked otherwise; [browse the pinned tree](https://github.com/kenotron-ms/muxterm/tree/aa6b581bd8d8ba5537d794c33beed00e5755d2b8).

## 1. Decision summary

**Recorded user decisions for this design:** one Mission Control UI and one voice bridge client, attaching to different conversation threads; no separate user-facing instances per workspace. One fleet-wide **Lobby**, provisionally summary-only, and one conversation thread per workspace. Focus changes are explicit, prominently visible in text, and spoken; answer context is announced by the system, not left to model obedience. **Mission Control** names the surface, assistant, and voice. Chief of Staff/COS role names are deprecated. muxterm remains the enclosing application; Dashboard remains its applet.

**Recommendations, not settled user decisions:** queue attention by default; offer opt-in interruption at safe audio boundaries. Use one server router with lazy, independently rooted sidecar processes per thread, and a fresh realtime provider session at each cross-thread voice attachment. Use `missioncontrol` for new machine-facing identifiers: one unambiguous Go/package/CLI namespace, without another acronym. These internal workers and provider connections are not extra Mission Control UIs, bridge clients, app servers, or autonomous workspace agents.

**Non-negotiable safety:** no silent focus stealing, including after idle time; no action in another workspace without an explicit resolved target and applicable confirmation. Navigation and conversation routing are separate. Switching, clearing, or archiving a conversation never closes panes/workspaces or kills lane work. Missing identity, stale correlation, or uncertain restoration fails visibly rather than guessing.

This document extends the existing [applet design](../design/mission-control.md), not a duplicate of it. PRs [#87](https://github.com/kenotron-ms/muxterm/pull/87) and [#93](https://github.com/kenotron-ms/muxterm/pull/93) were inspected; no equivalent active multi-channel design was found before this PR. Two earlier decisions need explicit reconciliation: the assistant role name at `docs/design/mission-control.md:360-370` is superseded, and D3.1's idle-threshold applet attention behavior (`:338-352`) **must never change conversation/voice focus**. Applet navigation may retain its own policy. Historic documents and PR evidence stay intact.

## 3. User flows and focus ownership

Use distinct labels, always visible near the composer/mic, not color alone:

```text
Conversation: machine / workspace name [short stable ID]
Voice: same thread | Lobby (summary only) | owned by another client | muted
Viewing terminal: machine / workspace name   (independent navigation)
```

Names must be safely rendered/escaped; duplicate or renamed workspaces retain identity labels. Apply existing palette and 44px target rules (`DESIGN.md:15-21,75-94,128-144`); add accessible focus text and live announcements as requirements of this design.

| Flow | Proposed behavior |
|---|---|
| Open Lobby | First visit selects Lobby explicitly in the UI; enabling the mic announces “Mission Control. Lobby, fleet summaries only.” It reads fresh fleet evidence and bounded summaries, not every conversation. |
| Focus a workspace | Select “Talk in this thread” from the thread picker or a labeled attention card. Resolve machine + stable workspace, preview target, commit switch, then enable input. Clicking a terminal tab, opening Files/Viewer/PRs, or an applet's attention jump does not route speech. A combined “Open and talk” action must say both. |
| Speak or type | Target is fixed at speech start; for text, at composer creation/first edit (draft stays with its thread). Show routing at submission and state answer context before playback. An utterance “switch to B and deploy it” switches only; require a new B-targeted turn/confirmation for work. |
| Another lane needs attention | **Recommend queue by default:** durable labeled item with reason, age, provenance and actions “Keep queued”, “Open thread”, “Interrupt at next safe boundary”. **Recommend opt-in interruption:** a short labeled notice only; it never switches or approves. If no reliable phrase boundary exists, wait for the whole audio turn to drain. Do not interrupt an approval prompt or the user's utterance. |
| Background completion | Append to originating thread, update its unread badge/attention item and eligible Lobby summary. Never insert full results or speak them in the current unrelated thread. “Summarize A's result” is scoped retrieval; reading the full result or acting on it requires an explicit thread/detail selection. |
| Reconnect | Fetch authoritative thread metadata, event cursor/gaps, pending approvals and focus revision. Restore the visible selection only after validation; mic is muted until lease and fresh provider attachment are acknowledged. Never replay recorded speech or resubmit an uncertain turn automatically. |
| Multiple browsers | Each browser has its own conversation selection/drafts/read cursor; neither broadcasts its navigation as another's focus. Text turns into the same thread serialize. One server-enforced voice lease belongs to a bridge/client, not a workspace or global last writer. Other browsers can read/type but get “voice in use”; takeover requires an explicit action. |

**Ownership recommendation:** one active speaking bridge lease across this Mission Control server, with server-issued client identity bound to the authenticated connection. The same client can renew; opening/reconnecting another tab does not acquire it. Explicit takeover fences the old lease immediately and disables its routing. New playback waits for old sink-stop acknowledgement or bounded lease expiry; if old audio silence cannot be established, remain muted and report the conflict. Do not claim the server can recall audio already buffered on a disconnected browser. Require browser heartbeat-loss muting, and verify it before takeover is enabled.

The lease owns voice focus. Other browsers may independently select B while voice remains on A, and must display that distinction. A voice-owner's explicit conversation switch uses the voice switch transaction below rather than changing text first and silently leaving the mic elsewhere. No model-selected workspace, tab focus, local-storage value, or notification is authoritative.

## 4. Durable thread model and storage

**Proposed v2 records** (illustrative schema, not existing interfaces):

```text
Thread: schema_version, thread_id (UUID), kind (lobby|workspace|legacy),
        machine_id?, workspace_uuid?, display_name, lifecycle,
        runtime_session_id (UUID), runtime_generation, storage_cwd,
        transcript_ref, last_event_seq, summary_ref, created_at, archived_at?
Binding: (machine_id, workspace_uuid) -> thread_id
Address: (machine_id, daemon_incarnation, live_workspace_id) -> workspace_uuid
Turn: turn_id, thread_id, runtime_generation, client_id, request_id,
      capture_id?, focus_epoch, lease_epoch?, submitted_at, dispatch_state
Event: event_id, thread_id, thread_seq, turn_id?, call_id?, approval_id?,
       runtime_generation, observed_at, causation_id?, replay
Focus: client_id, thread_id, focus_epoch; voice adds lease_id, lease_epoch,
       provider_session_id, attachment_generation
Summary: thread_id, source_event_range, source_turn_ids, evidence_time,
         generated_at, machine/recovery_epoch, freshness, text
```

`thread_id` is never a name or `wN`. The identity stage adds a persisted machine UUID (local included), workspace UUID in registry/snapshot/protocol, and daemon-incarnation ID for live addresses. `HostRef.ID`/connection labels become aliases to that machine identity, not permission to rebind on a hostname change. Machine UUID cloning/reinstall is a conflict requiring explicit reconciliation, not automatic history attachment.

Preserve workspace UUID on rename and restore; creation/duplication gets a new UUID. The reported **w69 → w4** restart is a motivating user observation, not a run verified here: with v2 identity, both addresses map to the same `(machine_id, workspace_uuid)`. For an old snapshot with no UUID, assign once and persist an upgrade ledger; ambiguous mappings stay **unbound**. Never infer identity from shared name, CWD, pane ID, position, or empty roster. Legacy remotes without identity capability remain read-only/unbound for durable threading until upgraded or explicitly bound; no fake durability claim.

**Storage recommendation:** one server-owned transactional local catalog under the XDG data `muxterm/missioncontrol/` namespace, containing binding/focus metadata, durable turn/event journal, summary references and migration ledger. SQLite is a candidate, subject to Go packaging review, not a new service requirement. Preserve full sidecar transcripts in the existing session-store format under unique UUID root sessions with recorded, immutable storage CWD/project slug. User workspace CWD is explicit scoped context, not the process's mutable persistence key. Store references, not duplicate full transcripts in two competing authoritative stores. Transcript persistence and journal append are not one transaction today: reconcile via immutable turn/runtime IDs and mark interrupted saves unknown; never automatically replay an externally effective operation to fill a gap.

Thread lifecycle: `active`, `detached` (workspace gone/unreachable), `archived` (read-only), `legacy` (read-only mixed history). Rename changes display only. Workspace closure updates binding/lifecycle but does not delete history. Archiving while turns/approvals exist is refused with an offer to wait; it does not cancel them. Reopening the same stable workspace can explicitly reactivate its thread; a new workspace with the old name cannot inherit it. No automatic retention deletion in this rollout.

## 5. Runtime isolation: one router, separate roots

**Recommended implementation boundary:** one Mission Control server router, a lazy per-thread supervisor registry, and one independent Python root-session process for each active thread (including Lobby). Reuse supervisor machinery, not the same supervisor/context. Each gets unique session ID, queue, broker, coordinator/hooks, tool objects, todo/goal state, prompt factory, cancellation, cost accounting, persistence callbacks and status/instruction paths. Use UUID runtime IDs rather than name-prefixed IDs: the generic agent recovery title matcher expects UUIDs (`internal/sessiond/agent_catalog.go:80-107`); sidecars are not themselves lane panes.

Add an exclusive owner lock per runtime store key; CLI and server must share the owner router, not instantiate a second writer. Today's CLI guard explicitly warns about two supervisors overwriting one transcript (`cmd/muxterm/cos_cmd.go:114-135`). Scope/aggregate `state.go` status publication, teardown and reconfiguration so one worker cannot overwrite or remove another's files. Do not inherit a parent's lane attribution into the thread workers; hooks receive explicit root/thread identity and do not overwrite an unrelated pane's roster row.

Shared data is immutable product policy/provider configuration, not conversation-derived content. Snapshot/version effective policy at turn admission; permitted tuning changes apply at per-thread idle boundaries. Assemble dynamic prompt/mention context from that thread only. Lobby and cross-thread retrieval use bounded, read-only capabilities; action dispatch validates machine/workspace/turn authority at the tool boundary, not merely in a prompt. Arbitrary tool reads of other Mission Control transcript stores must not bypass that boundary. User-added memory/hooks/bundles may inject global history: inventory and restrict those contributions for threaded mode, or refuse enablement until isolated. This is context isolation, **not an OS sandbox against hostile tools**.

Reject the cheaper message-swap approach: serialization plus `set_messages` still leaves non-message state shared, and callbacks may persist after selection changes. Multiple roots in one Python process also leave module-global hook maps and external compaction behavior unproven. Separate processes align with current session boundaries without changes to amplifier-agent or other upstream dependencies. Their isolation is still a **design hypothesis requiring the real-runtime harness**, especially resume, compaction, module persistence and external memory hooks.

Bound resource use: lazy start; idle eviction only after queue empty, no approvals/tool callbacks, and confirmed persistence; never evict work because another thread gains focus. A configured worker cap queues new starts with visible status, not a forced cancellation. Sidecar death marks active effects unknown and leaves originating thread identity fixed. Pending approvals reconcile from durable state, not a lossy broker alone.

## 6. Atomic turn routing and audio fencing

Atomicity means a **server routing/journal commit**, not a claim of distributed atomicity across browser, provider and disk.

### Required v2 boundary

The negotiated `missioncontrol-*` protocol must carry these fields; names are proposed, semantics normative:

```text
Command: protocol_version=2, request_id, op, thread_id, expected_runtime_generation
  submit_text: draft_ref, text
  submit_voice: capture_id, expected_focus_epoch, lease_id,
                expected_lease_epoch, attachment_generation
  approve: turn_id, approval_id, decision, confirmation_ref
  cancel: turn_id, confirmation_ref
  reset: preview_id, confirmation_ref
  history: after_thread_seq, limit
Receipt/Event: protocol_version, request_id?, event_id, thread_id,
               runtime_generation, thread_seq, turn_id?, status/rejection_code
```

Client identity comes from the authenticated connection, never a supplied `client_id`. Server-created captures/draft references supply immutable targets; IDs supplied by models are not authority. Missing/mismatched fields reject before queueing, provider/tool dispatch or narration. Only the negotiated v1 adapter may use the explicit legacy view. Confirmation references bind operation, target, generation and expiry; a confirmation for A cannot authorize B.

For text, obtain a server-issued draft reference binding owner, thread and creation epoch. Focus changes do not invalidate or retarget that draft: require reselection of A before submitting A's saved draft. Voice requires the stricter current capture/lease fence. Both reject a changed runtime generation until the user reviews/rebinds the draft or repeats speech.

1. **Capture:** before forwarding microphone bytes, the owning bridge obtains a capture token bound to `{thread_id, focus_epoch, lease_epoch, attachment_generation}`. Maintain that binding at utterance start, not STT completion. Gate microphone/turn admission during switches; use push-to-talk if continuous VAD cannot establish this ordering. Map provider input `item_id`, response IDs and tool `call_id` to the capture. The existing harness already correlates committed audio item IDs (`test/voice-e2e/exit-conversation.mjs:548-568`); production parsing needs that seam. A delayed/unmapped call is quarantined/rejected, never assigned to “current focus”.
2. **Admission:** server verifies client ownership, target lifecycle, binding, runtime generation and the input-specific draft/capture fence above, then durably records the request before queueing. Same request ID returns the original acknowledgement; differing payload under it is an error. A stale, not-yet-admitted A voice capture after a committed switch to B is rejected with “not submitted to A”; it is **not** rerouted to B.
3. **Execution:** admitted turns remain in their originating per-thread queue, even after focus changes. Offer “leave queued in A” (default) or explicit “cancel queued A turn”; moving to B requires cancel plus a new confirmed submission. Approval/cancel/clear/history require thread and operation IDs; no global-last fallback. Actions in a workspace other than the thread's bound workspace are refused unless explicitly targeted/confirmed through the scoped dispatch boundary.
4. **Results:** append events to the turn's original thread/runtime generation. Old-epoch results are valid history there, not permission to speak in a new attachment. Deduplicate by durable event ID and per-thread sequence; detect gaps and fetch authoritative replay/pending state. Drop/quarantine events from retired clear generations. Replays never re-narrate, reapprove, or redispatch tools. External side effects remain at-most-one attempted dispatch where possible, not a promise of exactly-once execution after a crash.

### Switch transaction

`missioncontrol-focus-prepare(target, expected_focus_epoch)` validates explicit user intent and target; the indicator says “Switch pending”, retaining old authoritative focus. For voice, prepare a **fresh provider session** with only the destination's bounded context, initially mic/speaker/tool-gated. One bridge client owns both candidate and retiring transport handles, with at most one active attachment. Never transplant a provider conversation or assume deleting its messages clears audio, tool, or response state.

Default mid-utterance/answer switch waits until capture admission/rejection and audio drain. The user may explicitly stop listening now: cancel generation, clear buffered playback, mute/close old sink and obtain the browser acknowledgement. Optional notification interruption waits for a supported phrase boundary or `output_audio_buffer.stopped`, **not merely `response.done`** (`internal/voice/sideband.go:332-354` distinguishes generation from audible delivery). No timer guesses a safe word boundary.

Commit uses compare-and-swap on expected focus/lease epochs, fences old tool callbacks/narration, and persists the new focus. New input/output is enabled only after old media is stopped and the client acknowledges the new binding. Deterministic UI text and a bridge-controlled spoken prefix say “Mission Control, now in B” and, for each answer, “Answering in B” (or “Lobby summary about A”). Use a serialized announcement playback segment, not a request that the conversational model remember to say it. If announcement or media acknowledgement fails, remain visibly muted; text can remain available with its explicit target.

Prepare failure leaves A selected and closes only the candidate; if old audio was already drained, report paused A rather than pretending uninterrupted playback. CAS conflict returns the authoritative selection; it cannot silently retry against a new epoch. Failure **after** commit leaves B selected but muted/reconnecting; going back to A requires a new visible switch and a new provider session. Never reuse a mixed provider context as rollback.

**Audio cancellation is not work cancellation.** Already dispatched tools/lane work continue in A; results and pending approvals remain in A with a labeled queued notification. “Stop work” is a separate targeted cancellation request with acknowledgement. Report any irreversible effect already performed and any uncertain completion; do not claim undo or replay an action because its answer was cut off. Before-dispatch cancelled captures perform no action.

### Clear is scoped and separate from switching

Recommend “Reset this thread's context” with a preview of thread, affected transcript/summary/todo state and retained audit history. Refuse while that thread has active/queued turns, approvals or unresolved callbacks; never cancel them implicitly. Fence admission, snapshot the old generation, create a clean root generation, then atomically select that generation without changing thread focus. Reset does not automatically mint realtime sessions: only if this thread owns the active voice attachment, fence old captures and use the same fresh-session/old-sink-acknowledgement switch transaction above. Otherwise defer attachment until explicit voice enablement. Only selected material transfers. Invalidate derived summaries; keep operation/lane ledger outside model context. Return retained/protected material to the browser (PR #129 notes its current protected list is dropped).

The thread ID stays stable; archived prior generations remain reviewable but are not silently reloaded into context or recovery fallbacks. “Reset” is not secure erasure of archives/backups. Age-based pruning can remain a distinct compatibility operation with its narrower guarantees. An explicit **global reset** must preview/enumerate all threads and require separate confirmation; it is not implied by clear in Lobby, and should stay disabled in initial rollout. None of these operations invokes sessiond close/kill. Unknown restored-lane state never authorizes deletion.

## 7. Summary-only Lobby and recovery

**Provisional policy:** Lobby trades seamless follow-ups for bounded, attributable orientation. Recommend an initial **8K-token dynamic context budget** (excluding fixed policy): fresh roster facts plus at most 20 summaries of 200 tokens each, recent Lobby dialogue within the remainder, no raw workspace transcripts/tool dumps. These numeric limits are tunable recommendations. Trim by explicit budget before prompt construction; never rely on opaque provider compaction to preserve scope. Store full Lobby history for review but do not feed it all back. A Lobby answer identifies truncation/omitted workspaces.

Each summary has thread/machine identity, source turn/event range, evidence and generation timestamps, last observed lifecycle, and recovery epoch. Refresh fleet reads on status questions and before any action in its actual workspace thread; a cached summary never establishes liveness or authorization. Suggested freshness threshold: 30 seconds for roster evidence, visibly stale afterwards; timestamps do not upgrade absent evidence to certainty. Summary-generated text is not equivalent to machine-checked state.

Follow-up choices: (a) “Show A's detail” opens A's explicitly labeled **read-only thread/detail view**, independent of conversation focus; Lobby receives only a cited bounded summary, or (b) “Talk in A” explicitly switches conversation/voice. Full detail narration requires that switch. No wholesale transcript import; selected transfers record source and consent. A Lobby spoken answer says “In Lobby, summarizing A as of …”. Lobby has no mutating workspace tools and cannot approve, cancel, reset or clear a workspace thread: commit a switch to that thread first. An explicitly labeled UI control in A's thread view is not a Lobby-model action.

**Recovery contract:** use `reconciling`, `observed`, `stale`, `unavailable`, `unknown` evidence states, separate from lane `working/blocked/done`. After restart, reconcile durable workspace bindings, restored pane/transcript evidence, current process ancestry and fresh producer roster declarations. Until complete, say “No declared sessions observed; restored agent state unknown,” not “no agents” or “all done”. Expiring reconciliation does not turn unknown into done. Preserve last-observed records with timestamps and completion provenance. Remote disconnection keeps history but removes claims of current liveness. Neither a transcript tail nor a restored pane alone proves the old process survived.

### Versioning, migration and downgrade policy

**Read old/write new is insufficient.** Proposed sequence, with no migration executed by this PR:

1. Ship a **compatibility floor release** first: understands v1 and v2, preserves unknown catalog versions by refusing writes, and honors a migration/owner lock. Server/browser/sidecar handshake advertises protocol and thread/identity capabilities; old peers remain in explicit legacy mode. Existing NDJSON additive rules (`internal/cos/events.go:5-16`) do not authorize silently stripping v2 routing fields. A sidecar lacking required capabilities cannot serve a threaded root.
2. Feature flag off retains the unchanged single legacy writer. Explicit migration preview lists the actual configured legacy session/store key (not just the default), checksums, backups, proposed bindings, and clients that must upgrade. Quiesce only that conversation's admitted turns/callbacks with consent; do not stop lanes. Atomically record a migration ID and immutable legacy archive reference. Keep original transcript/event/audit files and recovery copies intact. New Lobby/workspace roots start empty. Selected transfers have source IDs, consent and an idempotency key; never replicate the mixed transcript into every thread.
3. While v2 is enabled, old unscoped clients get **read-only legacy history and an upgrade-required rejection for mutation/voice**. Never map `cos-turn` or `cos-clear` to another browser's selected thread. Negotiated legacy transports may address the explicit legacy view, not strip targets from v2. Unknown v2 fields are not a fallback route. New server + old sidecar and new client + old server stay feature-off/refused, visibly. One adapter chooses one event vocabulary per connection, with stable event IDs/cursors across reconnection; duplicate requests return the prior receipt, not a second submission.
4. Rollback within the compatibility floor disables v2 admission and fences attachments. V1 mutation may resume only after v2 roots/callbacks reach terminal or safely fenced states and release writer locks. On timeout, record uncertain effects and keep both modes read-only; reporting uncertainty alone does not authorize switching writers. Snapshot journal/cursors before changing the active-mode pointer. V2 stores remain intact/read-only and exportable; v1 resumes from a recorded legacy checkpoint as a **new segment**, preserving the archived original. Do not flatten workspace histories into it. Re-upgrade uses the same migration ledger, avoiding repeated imports/events. Config migration backs up both schemas and checksums; downgrade materializes a frozen v1 view only after conflict review, never overwriting divergent personal edits.
5. Older-than-floor binaries cannot enforce this lock/schema policy: unsupported against v2 data. A deliberate downgrade must first export/snapshot all v2 data and use a separate, frozen v1-compatible store/config root with v2 preserved offline. Explain that post-migration threads are unavailable to that binary, **not lost**. Never have both generations writing shared transcript paths. Alias removal requires the floor's announced support window, an explicit compatibility inventory review and successful downgrade/re-upgrade rehearsals, not elapsed time or hypothetical analytics alone.

Cross-repo follow-ups are contract review for Amplifier session-store/compaction and shipped bundle namespace consumers, plus realtime provider correlation/audio guarantees. This plan changes no amplifier-agent or other upstream dependency; if an essential guarantee is unavailable locally, keep the feature off and raise a separate dependency proposal. Do not rewrite active assistant instructions, caches or runtime configuration as part of naming propagation.

## 10. Proposed verification harness and enablement gate

Use deterministic provider fixtures at the external API edge, barriers rather than sleeps, a fake microphone/audio fixture, temporary stores and a real unrelated lane process. This is not a new unit-test suite. Fresh fixtures per run; never target production, hand-roll a host server, or reuse another worktree's daemon. No cloud resources are required for deterministic scenarios.

## 11. Remaining decisions, conflicts and delivery boundary

- Confirm process-per-thread memory/latency budget and eviction limits after measurement; do not weaken isolation to meet a speculative target.
- Confirm summary-only Lobby after prototype use; queue-default/interruption, numeric budgets and per-client voice-lease policy are recommendations still requiring product acceptance.
- Choose/pin catalog transaction implementation and machine UUID transport capability; handle old remotes and cloned installations explicitly.
- External context/compaction, optional global memory hooks and provider input/audio correlation are **unverified dependencies**. Fail closed or remain feature-off if guarantees cannot be demonstrated locally; no upstream change is hidden in this plan.
- Naming supersedes the old role decision; public wire, bundle URI, protected config paths, UUID-only recovery and diagnostic parser compatibility prevent a global search/replace. Generic applet idle navigation is not permission for conversation focus theft. Historical names remain searchable through this mapping.
- Repository policy bans new unit tests despite existing tests and PR #129. Proposed gates use real-browser/sessiond integration plus real sidecar roots, with external deterministic fixtures and later live voice, reconciling that policy with the required safety tests.

**This PR changes this document only.** No production implementation, migration, runtime configuration, active instructions, dependency code, services, workspace/pane closure, live UI testing or cloud resources. Static/source review validates the design artifact and references, not runtime behavior. Implementation and enablement require the staged evidence above.
